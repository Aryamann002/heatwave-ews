# PRD.md — Extreme Heatwave Early Warning & Human Thermal Stress Index

Sponsor context: Ministry of Earth Sciences (MoES). Category: Software. Theme: Disaster Management.

## 1. Problem

Heatwaves in India are increasing in frequency and intensity. Air temperature alone under-describes danger, especially where humidity is high. Authorities need (a) an early view of where heat exposure will become critical, (b) a measure of physiological strain rather than just temperature, and (c) a tool that turns that into action.

## 2. Users

| User | Need | Success looks like |
|------|------|--------------------|
| District/city disaster officer | Know which wards need action in the next 1–5 days, and why | Can approve and dispatch an advisory in under 2 minutes |
| State admin | Compare districts, allocate resources | Sees ranked districts with reasoning |
| Health department | Anticipate hospital load | Sees lagged-risk view |
| Public (read-only stretch) | Simple local advisory | Understands what to do |

## 3. Scope (in)

1. Ingest open meteorological data (T, RH, wind, solar radiation).
2. Compute UTCI (primary), estimated WBGT, Heat Index.
3. Composite Human Thermal Stress Index (proposed, configurable).
4. Heatwave / critical-stress probability forecast for 1–5 lead days, calibrated.
5. IMD-style colour-coded alerts, with reasoning trace, reproducing IMD criteria as one track.
6. Interactive GIS dashboard: map, district ranking, time series, alert detail, advisory approval, response task board.
7. Advisory drafts in English + Hindi (human-approved).
8. Evaluation report with leave-one-year-out validation.

## 4. Non-goals

- Producing a new global weather model.
- Replacing IMD's official warnings.
- Real SMS/telecom delivery.
- Predicting mortality as a modelled output.
- Individual-level health advice.

## 5. Success metrics

Split into what can and cannot be measured in a hackathon.

**Measurable now**
- Index correctness: computed UTCI matches published reference values within tolerance in unit tests.
- Forecast skill vs baselines (persistence, raw forecast + IMD thresholds, climatology) on leave-one-year-out: POD, FAR, CSI, Brier.
- Calibration: reliability curve slope near 1 on holdout.
- Pipeline reliability: N consecutive scheduled runs without manual intervention.
- Dashboard: alert-to-approved-advisory flow completes end-to-end.

**Not measurable in a hackathon (do not claim)**
- Lives saved. There is no basis for this claim from a prototype.
- Real-world adoption.

## 6. Key assumptions to challenge

1. UTCI is an appropriate primary index for India. (Literature supports this, but at least one India study favoured WBGT for hot-arid outdoor settings. Both are shown.)
2. Composite weights are reasonable. They are **unvalidated**. A sensitivity analysis substitutes for false precision.
3. AI/IFS forecasts are good enough humidity-wise. Evidence suggests otherwise for some models; a correction step exists for this.
4. Census-based vulnerability is acceptable despite age (2011).

## 7. Risks

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| Overstated claims to jury | Medium | High (credibility) | Claims register; only report measured results |
| Data access delays (CDS, IMD) | High | Medium | Prefetch day 1; use Open-Meteo history as fallback |
| Model does not beat IMD-threshold baseline | Medium | Medium | Frame ML as calibration + impact translation; report honestly |
| Scope creep (downscaling, nowcasting) | High | High | Ladder: ship rung 1 first |
| Boundary/licence problems | Low–Med | High | Use sanctioned boundaries; log source |

## 8. Definition of done (prototype)

- One-command local run.
- Operational pipeline runs on a schedule and populates the dashboard.
- Evaluation report generated by a script, not hand-edited.
- README lists every limitation stated in this repo's docs.
- A demo script covers: normal day → dry-heat event → humid-heat event → advisory approval → task dispatch.
